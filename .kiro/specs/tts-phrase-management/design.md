# TTS Phrase Management System Design

## Overview

The TTS Phrase Management System enhances the existing presentation workflow by adding intelligent text-to-speech generation with contextual style adaptation. The system uses a dual-engine approach: Google's advanced Gemini TTS for most languages with natural language style prompts, and traditional Google TTS for Cantonese/yue-HK. The system analyzes speaker notes to determine appropriate delivery style and organizes generated audio files in a structured directory system similar to the existing visual assets management.

## Integration with Existing Workflow

The TTS Phrase Management System integrates into the existing presentation processing workflow at specific points without disrupting current functionality:

### Current Workflow Integration Points

1. **After Notes Generation**: TTS processing occurs after the `NotesGenerator` creates speaker notes
2. **Parallel to Visual Generation**: TTS runs alongside the `VisualGenerator` to avoid blocking
3. **Uses Existing PromptRewriter**: Leverages the current `PromptRewriter` system for style adaptation
4. **Follows Storage Patterns**: Uses the same directory organization as visual assets

### 2. TTS Style Adapter

Adapts the existing PromptRewriter system to generate TTS style prompts by analyzing speaker notes and using the LLM-powered rewriting capabilities.

```python
class TTSStyleAdapter:
    """
    Adapts the existing PromptRewriter system for TTS style prompt generation.
    Uses the LLM-powered rewriting capabilities to create contextual TTS prompts.
    """
    
    def __init__(self, prompt_rewriter: PromptRewriter):
        """Initialize with existing PromptRewriter instance."""
        self.prompt_rewriter = prompt_rewriter
    
    def generate_tts_style_prompt(
        self,
        speaker_notes: str,
        slide_content: str,
        language_code: str,
        base_tts_prompt: str = None
    ) -> str:
        """
        Generate TTS style prompt using the existing PromptRewriter system.
        
        Args:
            speaker_notes: Speaker notes containing style indicators
            slide_content: Slide text content for context
            language_code: Target language for TTS
            base_tts_prompt: Base TTS instruction template
            
        Returns:
            Generated style prompt for Gemini TTS
        """
        # Create base TTS prompt if not provided
        if not base_tts_prompt:
            base_tts_prompt = self._create_base_tts_prompt(language_code)
        
        # Create style guidelines from speaker notes analysis
        style_guidelines = self._analyze_speaker_notes_to_style(
            speaker_notes, slide_content
        )
        
        # Use PromptRewriter to create TTS-specific style prompt
        rewrite_request = f"""BASE_PROMPT:
{base_tts_prompt}

STYLE_GUIDELINES:
{style_guidelines}

STYLE_TYPE: tts_speech

CRITICAL REQUIREMENT: This is for text-to-speech generation using Gemini TTS. The output should be a natural language instruction that tells the TTS engine how to speak the content. Focus on:
1. Speaking tone and manner (formal, casual, enthusiastic, etc.)
2. Pace and rhythm instructions
3. Emphasis and emotional expression
4. Language-appropriate cultural considerations

Please rewrite the base prompt to create a natural language TTS instruction that incorporates the speaking style from the guidelines."""
        
        try:
            # Use the existing rewriter with retry logic
            tts_prompt = self.prompt_rewriter._run_rewriter_with_retry(
                rewrite_request, "tts_style"
            )
            return tts_prompt
            
        except Exception as e:
            logger.warning(f"TTS style prompt generation failed, using fallback: {e}")
            return self._create_fallback_prompt(style_guidelines, language_code)
    
    def _create_base_tts_prompt(self, language_code: str) -> str:
        """Create base TTS prompt template."""
        return f"""You are a professional speaker delivering presentation content in {language_code}. 
Your goal is to communicate clearly and effectively to your audience. 
Speak the following content with appropriate tone and delivery."""
    
    def _analyze_speaker_notes_to_style(
        self, 
        speaker_notes: str, 
        slide_content: str
    ) -> str:
        """
        Convert speaker notes into style guidelines format.
        This creates the style input for the PromptRewriter system.
        """
        if not speaker_notes or not speaker_notes.strip():
            return self._get_default_professional_style()
        
        # Analyze the speaker notes to extract style information
        style_analysis = self._extract_style_indicators(speaker_notes, slide_content)
        
        # Convert analysis to style guidelines format
        style_guidelines = f"""SPEAKING STYLE ANALYSIS:

Detected Tone: {style_analysis['tone']}
Pace Indicators: {style_analysis['pace']}
Emphasis Points: {', '.join(style_analysis['emphasis_words']) if style_analysis['emphasis_words'] else 'None'}
Emotional Context: {', '.join(style_analysis['emotions']) if style_analysis['emotions'] else 'Neutral'}
Presentation Type: {style_analysis['presentation_type']}

STYLE GUIDELINES:
{style_analysis['style_description']}

DELIVERY INSTRUCTIONS:
{style_analysis['delivery_instructions']}"""
        
        return style_guidelines
    
    def _extract_style_indicators(self, speaker_notes: str, slide_content: str) -> dict:
        """Extract style indicators from speaker notes using pattern matching."""
        normalized_notes = speaker_notes.lower().strip()
        normalized_content = slide_content.lower().strip()
        
        # Style patterns (simplified from original complex analysis)
        style_patterns = {
            "formal": ["formal", "professional", "academic", "official", "structured"],
            "casual": ["casual", "informal", "conversational", "friendly", "relaxed"],
            "enthusiastic": ["exciting", "energetic", "passionate", "dynamic", "enthusiastic"],
            "technical": ["technical", "detailed", "precise", "step-by-step", "systematic"],
            "narrative": ["story", "narrative", "journey", "experience", "example"]
        }
        
        # Detect dominant tone
        tone_scores = {}
        for tone, patterns in style_patterns.items():
            score = sum(1 for pattern in patterns 
                       if pattern in normalized_notes or pattern in normalized_content)
            if score > 0:
                tone_scores[tone] = score
        
        dominant_tone = max(tone_scores, key=tone_scores.get) if tone_scores else "professional"
        
        # Detect pace
        pace = "normal"
        if any(word in normalized_notes for word in ["slowly", "carefully", "pause"]):
            pace = "slow"
        elif any(word in normalized_notes for word in ["quickly", "rapidly", "brief"]):
            pace = "fast"
        
        # Extract emphasis words
        emphasis_words = []
        emphasis_triggers = ["important", "key", "critical", "emphasize", "highlight"]
        for trigger in emphasis_triggers:
            if trigger in normalized_notes:
                # Simple extraction of nearby words
                words = normalized_notes.split()
                for i, word in enumerate(words):
                    if trigger in word and i + 1 < len(words):
                        emphasis_words.append(words[i + 1])
        
        # Detect emotions
        emotions = []
        emotion_patterns = {
            "confident": ["confident", "certain", "sure"],
            "enthusiastic": ["excited", "thrilled", "amazing"],
            "cautious": ["careful", "consider", "might"],
            "urgent": ["urgent", "critical", "immediately"]
        }
        
        for emotion, patterns in emotion_patterns.items():
            if any(pattern in normalized_notes for pattern in patterns):
                emotions.append(emotion)
        
        # Create style description
        style_descriptions = {
            "formal": "Professional, authoritative, and structured delivery appropriate for business or academic settings.",
            "casual": "Friendly, conversational tone as if speaking to colleagues or friends.",
            "enthusiastic": "Energetic, passionate delivery that conveys excitement and engagement.",
            "technical": "Precise, methodical explanation with emphasis on accuracy and clarity.",
            "narrative": "Storytelling approach with natural flow and engaging rhythm.",
            "professional": "Clear, professional delivery suitable for general presentation contexts."
        }
        
        delivery_instructions = []
        if pace == "slow":
            delivery_instructions.append("Speak slowly and deliberately, allowing time for comprehension.")
        elif pace == "fast":
            delivery_instructions.append("Maintain a brisk but clear pace.")
        
        if emphasis_words:
            delivery_instructions.append(f"Give special emphasis to: {', '.join(emphasis_words[:3])}")
        
        if emotions:
            delivery_instructions.append(f"Convey {emotions[0]} emotion in your delivery.")
        
        return {
            "tone": dominant_tone,
            "pace": pace,
            "emphasis_words": emphasis_words,
            "emotions": emotions,
            "presentation_type": self._detect_presentation_type(normalized_notes, normalized_content),
            "style_description": style_descriptions.get(dominant_tone, style_descriptions["professional"]),
            "delivery_instructions": " ".join(delivery_instructions) if delivery_instructions else "Use clear, natural delivery."
        }
    
    def _detect_presentation_type(self, notes: str, content: str) -> str:
        """Detect presentation type from content."""
        type_indicators = {
            "academic": ["research", "study", "analysis", "theory"],
            "business": ["strategy", "revenue", "market", "growth"],
            "training": ["learn", "practice", "skill", "procedure"],
            "technical": ["system", "implementation", "configuration"]
        }
        
        combined = f"{notes} {content}"
        for ptype, indicators in type_indicators.items():
            if any(indicator in combined for indicator in indicators):
                return ptype
        return "business"
    
    def _get_default_professional_style(self) -> str:
        """Return default professional style guidelines."""
        return """SPEAKING STYLE ANALYSIS:

Detected Tone: professional
Pace Indicators: normal
Emphasis Points: None
Emotional Context: Neutral
Presentation Type: business

STYLE GUIDELINES:
Professional, clear, and authoritative delivery appropriate for business presentations. 
Maintain engagement while conveying information accurately and efficiently.

DELIVERY INSTRUCTIONS:
Use clear, natural delivery with appropriate pacing for comprehension."""
    
    def _create_fallback_prompt(self, style_guidelines: str, language_code: str) -> str:
        """Create fallback prompt when LLM rewriting fails."""
        return f"""Speak in a professional, clear manner appropriate for a presentation in {language_code}. 
        
Based on the content context: {style_guidelines[:200]}...
        
Deliver the content with appropriate tone and pacing for your audience."""
```

### 4. TTS Engine Implementations

#### Gemini TTS Engine

```python
class GeminiTTSEngine:
    def __init__(self, client: texttospeech.TextToSpeechClient):
        self.client = client
        self.model_id = "gemini-2.5-flash-tts"  # Default model for low latency
        self.pro_model_id = "gemini-2.5-pro-tts"  # For complex style requirements
    
    # Voice mapping for different languages
    VOICE_MAPPING = {
        "en-US": ["Aoede", "Callirrhoe", "Kore", "Zephyr"],  # Female voices
        "zh-CN": ["Leda", "Pulcherrima", "Vindemiatrix"],
        "ja-JP": ["Despina", "Erinome", "Laomedeia"],
        "ko-KR": ["Gacrux", "Sulafat"],
        "fr-FR": ["Autonoe", "Achernar"],
        "de-DE": ["Charon", "Fenrir", "Iapetus"],  # Male voices for formal German
        "es-ES": ["Orus", "Puck", "Umbriel"]
    }
    
    async def synthesize_speech(
        self,
        text: str,
        style_prompt: str,
        voice_config: VoiceConfig,
        language_code: str
    ) -> AudioResult:
        """
        Synthesize speech using Gemini TTS with style control.
        
        Example style prompts generated:
        - "Speak in a professional, clear manner suitable for a business presentation. 
           Give special emphasis to these key concepts: security, compliance. 
           This is a business presentation, so maintain professionalism and engagement."
        
        - "Use a friendly, conversational tone as if explaining to a colleague. 
           Speak slowly and deliberately, allowing time for absorption. 
           This is training material, so focus on clear instruction."
        """
        # Select appropriate model based on style complexity
        model = self._select_model(style_prompt)
        
        # Build the synthesis request
        request = self.build_synthesis_request(
            text, style_prompt, voice_config, language_code, model
        )
        
        try:
            # Call Gemini TTS API
            response = await self.client.synthesize_speech(request)
            
            # Process response and create result
            return AudioResult(
                audio_data=response.audio_content,
                public_url="",  # Will be set by storage manager
                cache_key="",   # Will be set by cache manager
                file_path="",   # Will be set by storage manager
                duration_seconds=self._estimate_duration(text),
                engine_used=TTSEngineType.GEMINI,
                style_prompt=style_prompt
            )
            
        except Exception as e:
            logger.error(f"Gemini TTS synthesis failed: {e}")
            raise TTSEngineError(f"Gemini TTS failed: {e}")
    
    def build_synthesis_request(
        self,
        text: str,
        style_prompt: str,
        voice_config: VoiceConfig,
        language_code: str,
        model: str
    ) -> dict:
        """
        Build Gemini TTS request with natural language prompts.
        
        Request structure follows Gemini TTS API format:
        {
            "model": "gemini-2.5-flash-tts",
            "prompt": "Natural language style instruction",
            "text": "Content to synthesize",
            "speaker": "Voice name",
            "audio_config": {...}
        }
        """
        # Select appropriate voice for language and gender preference
        available_voices = self.VOICE_MAPPING.get(language_code, self.VOICE_MAPPING["en-US"])
        selected_voice = self._select_voice(available_voices, voice_config.gender)
        
        return {
            "model": model,
            "prompt": style_prompt,
            "text": text,
            "speaker": selected_voice,
            "audio_config": {
                "audio_encoding": "MP3",
                "speaking_rate": voice_config.speaking_rate,
                "pitch": voice_config.pitch,
                "volume_gain_db": voice_config.volume_gain_db
            }
        }
    
    def _select_model(self, style_prompt: str) -> str:
        """Select appropriate Gemini TTS model based on style complexity."""
        # Use Pro model for complex style requirements
        complex_indicators = [
            "emphasis", "emotion", "multiple", "complex", "nuanced", 
            "storytelling", "dramatic", "varied pace"
        ]
        
        if any(indicator in style_prompt.lower() for indicator in complex_indicators):
            return self.pro_model_id
        
        return self.model_id  # Default to Flash for speed
    
    def _select_voice(self, available_voices: List[str], preferred_gender: str) -> str:
        """Select voice based on gender preference and availability."""
        # Gender mapping for voices (simplified - in reality would be more comprehensive)
        female_voices = {"Aoede", "Callirrhoe", "Kore", "Zephyr", "Leda", "Pulcherrima", 
                        "Vindemiatrix", "Despina", "Erinome", "Laomedeia", "Gacrux", 
                        "Sulafat", "Autonoe", "Achernar"}
        
        if preferred_gender.lower() == "female":
            female_available = [v for v in available_voices if v in female_voices]
            return female_available[0] if female_available else available_voices[0]
        else:
            male_available = [v for v in available_voices if v not in female_voices]
            return male_available[0] if male_available else available_voices[0]
    
    def _estimate_duration(self, text: str) -> float:
        """Estimate audio duration based on text length."""
        # Rough estimation: ~150 words per minute average speaking rate
        word_count = len(text.split())
        return (word_count / 150) * 60  # Convert to seconds
```

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system-essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

After analyzing the acceptance criteria, I've identified the following correctness properties that can be validated through property-based testing:

### Property 1: Directory Structure Consistency
*For any* presentation and language combination, the TTS system should create directories following the exact pattern `{base_name}_{language_code}_speech`
**Validates: Requirements 1.1**

### Property 2: File Naming Convention Adherence
*For any* generated audio file, the filename should contain both slide number and content hash components
**Validates: Requirements 1.2**

### Property 3: Language Directory Separation
*For any* set of languages processed, each language should have its own separate speech directory
**Validates: Requirements 1.3**

### Property 4: Content Hash Normalization Consistency
*For any* text content with equivalent meaning but different formatting, the normalized content hash should be identical
**Validates: Requirements 1.4**

### Property 5: Cache Hit Behavior
*For any* identical content and style parameters, the second generation attempt should result in a cache hit without new TTS calls
**Validates: Requirements 2.1, 2.2**

### Property 6: Cache Invalidation on Change
*For any* content where either text or style parameters change, a new audio file should be generated with a different content hash
**Validates: Requirements 2.3**

### Property 7: Engine Selection for Cantonese
*For any* language code "yue-HK" or Cantonese variant, the system should always select Traditional TTS engine
**Validates: Requirements 3.1**

### Property 8: Gemini TTS Usage for Supported Languages
*For any* language in the Gemini TTS supported set (excluding Cantonese), the system should use Gemini TTS with style prompt generation
**Validates: Requirements 3.2**

### Property 9: Style Analysis Consistency
*For any* speaker notes with clear style indicators (formal, casual, technical), the style analysis should consistently identify the appropriate tone category
**Validates: Requirements 6.1**

### Property 10: Default Style Fallback
*For any* slide with missing or empty speaker notes, the system should apply default professional presentation style
**Validates: Requirements 6.4**

### Property 11: Error Isolation
*For any* batch processing operation where one slide fails, the remaining slides should continue processing successfully
**Validates: Requirements 4.3**

### Property 12: MP3 Format Compliance
*For any* generated audio file, the output should be a valid MP3 format that can be played by standard audio players
**Validates: Requirements 5.1**

### Property 13: URL Accessibility
*For any* generated audio file uploaded to cloud storage, the returned public URL should be accessible and serve the correct audio content
**Validates: Requirements 5.4**

### Property 14: Parallel Processing Independence
*For any* set of slides processed in parallel, the results should be identical to sequential processing (order independence)
**Validates: Requirements 4.2**

### Property 15: Cache Metadata Consistency
*For any* cached audio file, the metadata should correctly link the content hash to the actual file location and the file should exist
**Validates: Requirements 2.4, 2.5**

## Error Handling

The system implements comprehensive error handling across all components:

### TTS Engine Failures
- **Gemini TTS Failures**: Automatic fallback to Traditional TTS with SSML enhancement
- **Traditional TTS Failures**: Retry with exponential backoff, then graceful degradation
- **Network Issues**: Local caching and retry mechanisms with circuit breaker pattern

### Style Analysis Failures
- **Ambiguous Speaker Notes**: Default to neutral professional tone with logging
- **Missing Context**: Use presentation type detection as fallback
- **Analysis Timeout**: Apply default style configuration

### Storage and Caching Failures
- **Cache Miss Handling**: Transparent regeneration with performance logging
- **Storage Upload Failures**: Local fallback with background retry
- **Directory Creation Issues**: Automatic permission handling and path validation

### Integration Failures
- **Pipeline Integration**: Non-blocking operation with status reporting
- **Concurrent Processing**: Thread-safe operations with proper resource management
- **Batch Operation Failures**: Individual slide error isolation

## Testing Strategy

The testing approach combines unit testing for specific functionality with property-based testing for universal correctness guarantees.

### Unit Testing Approach
Unit tests will focus on:
- Individual component functionality (StyleAnalyzer, EngineSelector, etc.)
- Error handling scenarios and edge cases
- Integration points between components
- Mock-based testing for external TTS API calls

### Property-Based Testing Approach
Property-based tests will use **Hypothesis** (Python) as the testing framework, configured to run a minimum of 100 iterations per property. Each property-based test will be tagged with comments explicitly referencing the correctness property from this design document using the format: **Feature: tts-phrase-management, Property {number}: {property_text}**

Key property test categories:
- **Directory and File Organization**: Testing path generation, naming conventions, and structure consistency
- **Caching Behavior**: Testing cache hits, misses, invalidation, and metadata consistency  
- **Engine Selection Logic**: Testing language-based engine selection and fallback behavior
- **Style Analysis**: Testing speaker notes analysis and style prompt generation
- **Error Handling**: Testing graceful degradation and error isolation
- **Format Compliance**: Testing MP3 generation and URL accessibility

### Integration Testing
- End-to-end workflow testing with real TTS engines
- Performance testing for batch operations
- Cloud storage integration testing
- Compatibility testing with existing presentation pipeline

### Test Data Generation
Property-based tests will use intelligent generators that:
- Generate realistic speaker notes with various style indicators
- Create diverse language combinations including edge cases
- Produce varied presentation structures and content types
- Simulate different error conditions and network scenarios

The dual testing approach ensures both concrete functionality verification through unit tests and universal correctness validation through property-based testing, providing comprehensive coverage of the TTS phrase management system.
