# TTS Directory Fix - MP3 Files in Visuals Directory

## Problem
MP3 audio files generated by TTS were being stored in a separate `cache/speech` directory instead of the same directory as the visual files, making video synthesis more complex.

## Solution
Updated the TTS storage manager to use the same directory as visual files (the visuals directory) instead of the separate cache/speech directory.

## Changes Made

### 1. Updated TTS Storage Manager (`services/tts/storage_manager.py`)

**Modified Constructor:**
```python
def __init__(self, storage_config: TTSStorageConfig, main_config=None):
    """Initialize storage manager with configuration."""
    self.config = storage_config
    self.main_config = main_config  # Optional main config for directory integration
    self.local_cache_dir = Path(storage_config.local_cache_dir)
    
    # Ensure local cache directory exists (fallback only)
    self.local_cache_dir.mkdir(parents=True, exist_ok=True)
```

**Updated Directory Path Generation:**
```python
def generate_speech_directory_path(self, presentation_id: str, language_code: str) -> str:
    # Try to use the main config's visuals directory if available
    if self.main_config:
        try:
            # Use the main config's visuals directory
            return self.main_config.visuals_dir
        except Exception as e:
            logger.warning(f"Failed to use main config visuals directory: {e}")
    
    # Try to create a temporary config to get the visuals directory pattern
    try:
        from config.config import Config
        # Create a temporary config to get the visuals directory pattern
        temp_config = Config(
            pptx_path=f"{presentation_id}.pptx",
            pdf_path=f"{presentation_id}.pdf",
            language=language_code
        )
        # Use the visuals directory instead of cache/speech
        return temp_config.visuals_dir
    except Exception as e:
        logger.warning(f"Failed to create temp config for visuals directory: {e}")
        # Fallback to original behavior if config is not available
        directory_name = self.config.directory_pattern.format(
            base_name=presentation_id,
            language_code=language_code
        )
        return str(self.local_cache_dir / directory_name)
```

## Directory Structure Before and After

```
    └── presentation_en_speech/

        ├── slide_2_<hash>.mp3
        └── ...
```

### After Fix:
```
generate/hkcomic/
└── presentation_en_visuals/
    ├── slide_1_reimagined.png
    ├── slide_1_<hash>.mp3
    ├── slide_2_reimagined.png
    ├── slide_2_<hash>.mp3
    └── ...
```

## Benefits

1. **Simplified Video Synthesis**: Only need to specify one directory for both slides and audio
2. **Better Organization**: All presentation assets in one logical location
3. **Reduced Complexity**: No need to manage multiple directory paths
4. **Consistent with Config**: Aligns with the config change where `speech_dir` returns `visuals_dir`

## Backward Compatibility

The changes include fallback mechanisms:
1. If main_config is not provided, creates a temporary config to get visuals directory pattern
2. If config creation fails, falls back to original cache/speech behavior
3. Existing TTS CLI utilities continue to work without modification

## Testing

Both scenarios tested successfully:
- ✅ With main_config: Uses visuals directory (`generate/hkcomic/test_en_visuals`)
- ✅ Without main_config: Falls back to visuals directory pattern (`generate/test_presentation_en_visuals`)

## Usage

After running `./run.sh --style-config hkcomic`, both slide images and MP3 audio files will be in the same directory:

```bash
# Video synthesis now works with single directory
python main.py --synthesize-video \
  --slides-dir generate/hkcomic/presentation_en_visuals \
  --video-output generate/hkcomic/presentation_video.mp4
```

The MP3 files are now stored alongside the visual files, making the video synthesis workflow much simpler and more intuitive.
